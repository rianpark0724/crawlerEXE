# 커밋 계획

PRD 17장의 작업 조각(S01–S19)을 **실행 가능한 작은 커밋**으로 나눈 계획. 총 100개 + 태그 5개.
Claude에게는 커밋 단위로 요청한다: "COMMITS.md S04-2 진행해 줘".

## 규칙

1. **커밋마다 게임이 실행돼야 한다.** 에러로 안 켜지는 상태로 커밋하지 않는다.
2. 커밋 하나 = 확인 가능한 변화 하나. 각 행의 "확인" 칸을 직접 보고 커밋한다.
3. 메시지 형식: `S04-2 feat(legs): 2관절 IK로 무릎 위치 계산`
   - 타입: `feat` 기능 · `fix` 버그 · `tune` 수치 조정 · `refactor` 구조 변경(동작 동일) · `content` 스테이지·배경 데이터 · `perf` 성능 · `docs` 문서 · `chore` 설정
   - 범위(괄호): `core` `body` `camera` `legs` `stage` `wave` `parts` `hit` `enemy` `ui` `tri` `orb` `save` `sound` `boss`
4. 계획에 없는 수정(버그, 수치 조정)이 생기면 번호 뒤에 알파벳을 붙인다: `S04-2a fix(legs): 무릎 꺾이는 방향 반대로 수정`.
5. 작업 조각이 끝나면 AI_LOG.md 항목을 쓰고 `docs:` 커밋으로 함께 올린다 (아래 표에서는 생략).
6. 마일스톤 끝에 태그: `git tag v0.2-mvp && git push --tags`.
7. 브랜치는 `main` 하나로 충분. 실험이 필요하면 `exp/이름` 브랜치에서 해 보고 합친다.
