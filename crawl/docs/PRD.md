## 1. 개요

웹페이지 속을 기어 다니는 크롤러가 되어, 흩어진 데이터를 **발로 밟아** 수집하고 백신을 피해 다음 페이지로 탈출하는 2D 탑다운 액션 게임.

### 1.1 핵심 재미 (모든 기능은 이 셋 중 하나를 강화해야 한다)
1. **살아 있는 다리** — 스프라이트 애니메이션 없이 IK로 매 프레임 계산하는 다리. 같은 걸음이 없다.
2. **발끝 판정** — 데이터는 발이 착지하는 순간에만 줍는다. 조작은 몸통, 결과는 다리.
3. **몸 = 상태창** — 체력바가 없다. 다리 수가 체력이고, 몸 모양이 조작 방식이다.

### 1.2 목표
- 2주 차 끝: □ 사각형으로 스테이지 1–3을 처음부터 끝까지 플레이할 수 있다 (MVP).
- 4주 차 끝: 크롤러 3종, 스테이지 6개 + 보스, 사운드, 점수·저장까지 완성.

### 1.3 비목표 (하지 않는 것)
- 실제 웹 접속·크롤링, 네트워크 기능 (본편 기준. 실제 페이지를 스테이지로 쓰는 아이디어는 21장 외전)
- 멀티플레이, 키보드 조작, 게임패드
- 스프라이트 시트 애니메이션 (모든 생물은 선·원·사각으로 절차적으로 그린다)
- 가로 스크롤 (페이지는 세로로만 스크롤)

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 크롤러 | 플레이어 캐릭터. 머리 + 마디들 + 다리들 |
| 마디 (segment) | 몸통을 이루는 도형 하나. 0번이 머리 |
| 다리 (leg) | 마디에 붙은 2관절 선. 어깨 → 무릎 → 발 |
| 발 (foot) | 다리 끝점. 바닥에 고정돼 있다가 걸음을 옮긴다 |
| 착지 (landing) | 발이 한 걸음을 끝내고 바닥에 닿는 순간. 수집 판정 시점 |
| 페이지 | 스테이지 하나. 폭 1280px, 세로로 긴 웹페이지 |
| 데이터 조각 | 수집 대상. 링크 단어 모양 |
| 다리 파츠 | 밟으면 크롤러가 자라는 아이템 |
| 출구 링크 | 목표 달성 후 밟으면 다음 페이지로 가는 오브젝트 |
| 무적 액션 | 우클릭 기능. 크롤러마다 모양이 다르다 (5.5) |

## 3. 플랫폼 · 기술 제약

- 창 1280 × 720, 목표 60fps.
- pico2d 좌표: 원점 왼쪽 아래, y 위로 증가. 월드/화면 좌표 분리 (10장).
- 그래픽은 선·원·사각형 위주. pico2d에 선 함수가 없으므로 1×1 픽셀 이미지를 늘리고 회전해 그린다.
- 의존성: pico2d + 표준 라이브러리.

## 5. 공통 시스템

### 5.1 몸통 따라가기
- 머리(마디 0)만 입력으로 움직인다.
- 마디 i는 마디 i−1과의 거리를 `SEG_SPACING = 19px`로 유지하며 끌려온다 (거리 제약).
- 예외: △ 삼각형은 경로 기록 방식 (6.2), □ 사각형 WAVE 중에는 늘어나는 제약 (6.1.3).

### 5.2 다리 — IK와 걸음
- 각 다리: 어깨 위치(마디 둘레의 고정점), 허벅지 L1, 종아리 L2, 발 위치(월드 좌표).
- 다리마다 무작위 개성: L1 15–24px, L2 17–30px, 임계 거리 11–20px, 걸음 시간 0.07–0.13초.
- **이상적인 발 위치** = 어깨에서 다리 방향으로 `(L1+L2) × 0.62–0.78` 떨어진 점 + 이동 속도 × 0.08초 (앞쪽으로 미리 딛기).
- **걸음 규칙**
  - 발과 이상적인 위치의 거리가 임계 거리를 넘으면 걸음을 시작한다.
  - 같은 마디의 반대쪽 다리가 걷는 중이면 기다린다 (번갈아 걷기).
  - 동시에 걷는 다리는 전체의 절반 이하.
  - 걸음은 걸음 시간 동안 시작점 → 목표점을 ease-in-out 보간.
  - 거리가 임계 거리 × 5를 넘으면 (순간이동 등) 즉시 이상적 위치로 옮긴다.
- **무릎 (2관절 IK)**: 어깨~발 거리 d (clamp: |L1−L2| < d < L1+L2),
  `cos α = (L1² + d² − L2²) / (2·L1·d)`, 무릎 = 어깨 + L1·(cos(θ ± α), sin(θ ± α)). θ = 어깨→발 방향, 부호는 다리 쪽(좌/우)으로 바깥으로 꺾이게.

### 5.3 발끝 수집
- 다리가 **착지하는 순간 한 번** 판정한다. 착지 지점 반경 `COLLECT_R = 18px` 안의 데이터 조각을 모두 수집.
- 몸통·이동 중인 발은 수집하지 않는다.
- 다리 파츠·출구 링크도 같은 방식(착지)으로 밟는다.

### 5.4 피격 · 체력
- **체력 = 다리 수.** 0이 되면 GAME OVER.
- **다리 피격**: 적의 판정 원과 다리의 두 선분(어깨–무릎, 무릎–발) 중 하나가 겹치면 그 다리가 잘린다 (−1).
- **몸통 피격**: 적과 마디(원 판정)가 겹치면 다리 2개를 잃는다 (꼬리 쪽 마디의 다리부터).
- 잘린 다리는 몸에서 떨어져 바닥에서 1초간 꿈틀거리다 사라진다 (연출).
- **마디 탈락** (□ △): 어떤 마디의 다리가 모두 없어지면 그 마디가 떨어져 나가고 앞뒤 마디가 이어진다. 머리는 탈락하지 않는다.
- 피격 후 `HIT_IFRAME = 1.0초` 무적, 몸이 깜빡인다.
- 다리 수에 따른 이동 속도 배율: 1–2개 ×0.6 / 3–5개 ×0.85 / 6–8개 ×1.0 / 9–12개 ×1.1.

### 5.5 우클릭 무적 액션 (공통 규칙)
- 모든 크롤러의 우클릭은 **짧은 무적 + 대가**를 포함한다. 무적은 최대 0.5–0.6초 수준.
- 재사용 대기시간이 있다. 대기 중에는 HUD에 표시.
- 무적 중에는 데이터를 수집하지 않는다.

## 6. 크롤러 3종

### 6.1 □ 사각형 BOX — 기본형 (MVP)
**6.1.1 이동**
- 머리가 커서 방향으로 회전(최대 3.5 rad/s)하며 전진.
- 속도: `120 px/s + 다리 한 쌍당 8 px/s`, 커서와 거리가 가까우면 감속 (거리 × 2.2 상한).
- 시작: 마디 3 · 다리 6 / 최대: 마디 6 · 다리 12.

**6.1.2 성장**
- 다리 파츠 하나 = **마디 +1, 다리 +2** (꼬리에 추가).

**6.1.3 우클릭 — WAVE (무적 파동)**
- 무적이 머리에서 꼬리로 한 마디씩 번진다.
  마디 i의 무적 구간 = `[i × 0.08, i × 0.08 + 0.4]` 초 (머리 i = 0).
- **무적인 마디는 위치가 고정**된다. 그 마디의 다리도 걸음을 옮기지 않는다.
- **늘어나는 이동 (B안)**
  1. 풀린 마디들은 평소처럼 머리를 따라가되, 마디 간격이 최대 `1.6 × 19 = 30px`까지 늘어날 수 있다.
  2. 머리는 가장 앞의 고정 마디로부터 `(그 앞의 풀린 마디 수) × 30px`까지만 갈 수 있다 (목줄).
  3. 파동이 지나가 마디가 풀릴수록 목줄이 길어진다.
  4. 꼬리까지 풀리면 늘어난 간격이 초당 최대 600px 속도로 19px로 복원된다.
  5. 늘어난 마디 사이 선은 가늘고 흐리게 그린다.
- 구현: 매 프레임 (a) 머리에서 뒤로 일반 따라가기, 고정 마디는 건너뜀 → (b) 가장 앞 고정 마디에서 머리 쪽으로 거슬러 30px 초과 간격을 당김 (FABRIK 방식, 이 단계에서 머리 위치도 제한됨).
- 재사용 대기: 파동 종료 후 2.0초.
- 참고: 마디 6개면 몸 전체가 동시에 무적인 순간이 없다 → 긴 몸은 타이밍이 까다롭다 (의도된 대가).

### 6.2 △ 삼각형 TRI — 돌진형 (3주 차)
**6.2.1 이동**
- 마우스 이동만으로는 움직이지 않는다. 커서 위치에 목적지 표시만.
- **좌클릭**: 머리가 즉시 클릭 지점을 향하고 `330 px/s`로 직진. **도착 전에는 방향을 바꿀 수 없다.** 돌진 중 좌클릭 무시.
- 도착 후 0.2초 경직 → 다음 클릭 가능.
- 다리 걸음 시간 ×0.55 (빠르게 종종거림).

**6.2.2 몸통 — 경로 기록**
- 머리가 지나간 점들을 기록하고, 마디 i는 그 경로를 따라 `i × 19px` 뒤의 점에 놓인다. 급선회하면 몸이 꺾인 모양 그대로 뒤따라온다.
- 경로 기록은 몸 길이 + 여유분만 유지.

**6.2.3 성장**: 다리 파츠 하나 = 마디 +1, 다리 +2. 시작 마디 3 · 다리 6.

**6.2.4 우클릭 — FOLD (접기)**
| 단계 | 시간 | 동작 |
|---|---|---|
| 접기 | 0.12초 | 꼬리부터 마디가 머리 쪽으로 당겨져 아코디언처럼 겹침, 다리 오므림 |
| 무적 | 0.5초 | 피격 없음, 수집 없음 |
| 반동 | 0.15초 | 머리 방향으로 40px 밀려나며 펴짐 |
| 경직 | 0.3초 | 클릭 입력 무시 |
- **돌진 중에도 사용 가능.** 사용하면 돌진이 그 자리에서 끝난다.
- 재사용 대기 2.5초.

### 6.3 ○ 원형 ORB — 구르기형 (3주 차)
**6.3.1 이동 (관성)**
- 커서 방향으로 가속, 마찰로 감속, 최고 속도 제한. n = 다리 수:
  - 마찰 `μ = 0.15 + 0.10 n` (/s), 속도에 `max(0, 1 − μ·dt)` 곱함
  - 가속 `a = 520 / (1 + 0.08 n)` (px/s²), 커서가 8px 이상 떨어져 있을 때만
  - 최고 속도 `v_max = 380 / (1 + 0.10 n)` (px/s)
- 다리 4개: 쭉 미끄러짐 · 7개: 보통 · 10개 이상: 잘 멈추지만 느림.

**6.3.2 몸과 다리**
- 마디 없음 (원 하나, 반지름 18px). 몸은 이동 거리만큼 회전한다.
- 다리는 원 둘레에 등간격으로 붙어 몸과 함께 돈다. 발은 5.2 규칙대로 IK로 딛고 걸음을 옮긴다 (구르면서 허둥지둥 걷는 모양).
- 시작 다리 4, 최대 12. 다리 파츠 하나 = **다리 +1만** (마디 없음).

**6.3.3 우클릭 — BALL (말기)**
- 다리를 몸에 붙여 공 모양, 0.5초 무적.
- 그동안 마찰 ≈ 0 (μ × 0.05) → 그대로 미끄러진다 (대가).
- 재사용 대기 2.0초.

## 7. 다리 파츠

| 종류 | 효과 | 대가 | 등장 |
|---|---|---|---|
| 일반 | 성장만 (6장 성장 규칙) | 없음 | MVP |
| 긴 다리 LONG | 붙은 다리 L1·L2 ×1.5 → 수집 범위 증가 | 걸음 시간 ×1.4, 다리 피격 선분도 길어짐 | 3주 차 |
| 가시 SPIKE | 착지 시 반경 40px 안의 백신 봇 1.5초 정지 | 드물게 등장 | 3주 차 |
| 자석 MAG | 착지 시 반경 60px 안의 데이터를 발 쪽으로 끌어당김 | 드물게 등장 | 3주 차 |

- 능력은 그 파츠로 생긴 다리에 붙는다. 그 다리를 잃으면 능력도 사라진다.
- 같은 파츠라도 크롤러별 결과가 다르다: 사각형 = 수집 폭 확장 / 삼각형 = 경로 위 몸 전체가 쓸어 담음 / 원형 = 마찰 증가.

## 10. 페이지 · 스크롤 · 카메라

웹페이지를 위에서 아래로 읽어 내려가는 느낌이 핵심이다.

### 10.1 페이지
- 폭 1280px 고정, 높이는 스테이지마다 다름 (720–2880px, 화면 1–4장).
- 시작 지점은 페이지 위쪽, 출구 링크는 대개 아래쪽.
- 배경: 그 페이지 종류(백과사전, 뉴스 등)를 닮은 **읽을 수 있는 흐린 글**과 화면 구성. 실제 사이트를 레퍼런스로 삼는다.
  - 스테이지 1 `/wiki/crawler`: **위키백과(Vector 2022) 어두운 테마**를 레퍼런스로 머리글·목차·탭·제목·안내문·본문·그림 틀·각주·분류·바닥글까지 재현. 내용은 **웹 크롤러 "생물"에 대한 짧은 토막글**(아직 밝혀진 게 거의 없는 느낌, 튜토리얼 힌트를 담음). 로고·그림은 직접 제작한다 — `tools/make_wiki_images.py`가 표준 라이브러리로 그려 `assets/images/`에 저장(파일이 없으면 X 자리 표시). 글꼴은 맑은 고딕(없으면 pico2d 기본 글꼴).
  - 페이지 글 전체 밝기는 `WIKI_ALPHA`로 낮춰 크롤러가 잘 보이게 한다.
- 데이터 조각은 이 글 위에 놓인 단어다. 외전(21장)에서는 실제 웹페이지 글과 링크 단어가 그대로 들어간다.

### 10.2 카메라
- **세로로만 스크롤.** `camera.y` = 화면 아래쪽 가장자리의 월드 y. 범위 `[0, page_height − 720]`.
- 머리가 화면 가운데 40% 구간(데드존)을 벗어나면 그쪽으로 따라간다. 부드럽게: `camera.y += (target − camera.y) × min(1, 6·dt)`.
- `/video/stream`: 카메라가 30 px/s로 자동으로 내려간다. 화면 **위쪽** 밖으로 밀려난 다리는 잘린다.

### 10.3 좌표 변환
- 화면 y = 월드 y − camera.y
- 마우스: `screen_y = 719 − event.y`, `world_y = screen_y + camera.y`. 카메라가 움직이면 커서 월드 좌표도 매 프레임 다시 계산 (마우스를 가만히 둬도 목표가 같이 움직인다).

### 10.4 HUD 스크롤바
- 화면 오른쪽 끝에 웹 브라우저 같은 세로 스크롤바. 현재 보이는 구간 + 출구 링크(주황 점) + 남은 데이터(하늘색 점)의 위치를 표시.

### 11.2 스테이지 JSON 스키마 (`data/stages/<id>.json`)
```json
{
  "id": "wiki",
  "url": "/wiki/crawler",
  "height": 1440,
  "goal": 10,
  "par_time": 90,
  "spawn": [640, 1300],
  "exit": [640, 160],
  "autoscroll": 0,
  "dark": false,
  "data": [[420, 1180, "href"], [700, 1100, "token"]],
  "parts": [[300, 900, "plain"], [980, 600, "plain"]],
  "enemies": [{"type": "bot", "x": 900, "y": 800}],
  "beams": [{"axis": "h", "period": 4.0, "offset": 0.0}],
  "walls": [[0, 700, 520, 24], [760, 700, 520, 24]],
  "background": "wiki",
  "page": "crawler"

```
- 좌표는 월드 좌표(y 위로 증가). `walls`는 `[x, y, w, h]` (왼쪽 아래 기준).

- `page`: 배경 문서 `data/pages/<page>.json`. 문서는 위치 없이 **내용만** 담고(제목·안내문·그림·블록 `p | h2 | h3 | list | refs | stub`·분류·바닥글), 배치는 코드(`world/wiki_layout.py`)가 한다. 글 표기: `[[링크]]` 파란 링크(데이터 조각 후보), `[[!링크]]` 빨간 링크, `**굵게**`, `[1]` 각주.

## 12. 화면 흐름 · HUD

```
TITLE ──▶ SELECT ──▶ PLAY ──▶ CLEAR ──▶ SELECT
  ▲                   │ └──▶ GAME OVER ──▶ SELECT / TITLE
  └──────────────────  └── ESC ⇄ PAUSE (계속 / 처음부터 / 타이틀로)
```
- MVP(2주 차)에서는 SELECT 없이 TITLE → 스테이지 1 → 2 → 3 순서로 진행.
- **HUD** (화면 좌표, 스크롤과 무관하게 고정)
  - 왼쪽 위 `DATA 07/10` · 가운데 위 현재 주소 `/news/today` · 오른쪽 위 `LEGS 6` + 막대(잃은 칸 빨강)
  - 오른쪽 아래 붙은 능력 파츠 `[LONG] [MAG]` · 우클릭 대기시간 게이지
  - 오른쪽 끝 스크롤바 (10.4)
- 체력바 없음. 크롤러 몸이 상태 표시.

## 13. 점수 · 해금 · 저장

- 점수 = 데이터 × 10 + 남은 다리 × 50 + max(0, par_time − 클리어 시간) × 5
- 등급: S ≥ 기준 × 1.2 / A ≥ × 1.0 / B ≥ × 0.8 / C 나머지 (기준 점수는 테스트 후 스테이지별 결정)
- 저장 `data/save.json`: 스테이지별 최고 점수·등급·사용 크롤러, 해금 상태. (git 제외)
- 개발자 옵션: 타이틀에서 F12 → 전부 임시 해금, `[DEV] ALL UNLOCKED` 표시, 저장하지 않음.

## 14. 사운드 (4주 차)

- 착지음: 다리마다 펜타토닉 5음 중 하나를 배정. 걸음이 화음이 된다.
- 크롤러별 음색: 사각형 짧은 클릭 · 삼각형 높은 틱 · 원형 둥근 톤.
- 효과음: 데이터 수집, 다리 손실, 파츠 획득, 출구 열림, 스캐너 경고, 무적 액션.
- 배경음: 스테이지마다 앰비언트 루프 1개. 음원 출처는 README에 기록.

## 15. 보스 — 거대 백신 (4주 차)

- 한 화면 아레나(높이 720). 중앙의 보스가 3초마다 격리 탄 4–6발을 퍼뜨린다 (탄 속도 160 px/s, 다리 피격 판정).
- 바닥에 패치 노드 3개(반경 30px)가 생긴다. **발 3개 이상이 동시에 노드 하나 위에 착지 상태**로 0.5초 유지되면 과부하 1회.
- 과부하 3회 = CLEAR. 과부하마다 탄 패턴이 빨라진다.

## 21. 외전 — 실제 웹페이지 크롤링 (MVP 이후 아이디어)

> 본편 범위가 아니다. 본편이 끝난 뒤 시간이 남으면 하는 확장. 일정에 넣지 않는다.

### 21.1 아이디어
- 실제 주소(URL)를 받아 **그 웹페이지의 글을 그대로 페이지로** 깔고, 그중 몇몇 단어가 **밟을 수 있는 데이터 조각으로 변한다.**
- 크롤러는 진짜 문서 위를 기어 다니며 진짜 링크 단어를 발로 긁어모은다 — "크롤러"라는 설정을 문자 그대로 구현.

### 21.2 방식 (검토 결과)
| 방식 | 판단 |
|---|---|
| 헤드리스 브라우저로 화면 스크린샷 | ✗ 큰 의존성, 이미지라 단어 위치를 알 수 없음 |
| 게임 실행 중 실시간 접속 | △ 시연 중 네트워크 실패 위험, 매번 결과가 달라 밸런스 불가 |
| **변환 도구 `tools/url_to_stage.py`** | ○ 표준 라이브러리(`urllib`, `html.parser`)로 HTML → 스테이지 JSON 저장. 게임은 JSON만 읽음 |

- 변환 규칙(초안): 제목·문단 → 페이지 글줄, `<a>` 링크 텍스트 → 데이터 조각 후보, 높이 = 글 길이, 목표 = 링크 수의 일부, 적·파츠는 규칙으로 자동 배치.
- 한계: 레이아웃은 문서 구조를 흉내 낼 뿐 실제 CSS 모양이 아님. 자바스크립트로 그리는 사이트(SNS·쇼핑몰 대부분)는 본문이 거의 없다 → 위키·뉴스 기사 위주.
- 추가 옵션: SELECT에 "주소 입력" — 실패하면 기본 스테이지로.

### 21.3 본편에서 미리 맞춰 둔 것
- 페이지 = 문서 JSON(`data/pages/`) + 위키 레이아웃 코드. 변환 도구는 실제 페이지의 제목·문단·링크를 **같은 문서 형식**(`[[링크]]` 표기)으로 내보내기만 하면 된다 — S03-2a에서 적용.
- 데이터 조각 = 문서 속 파란 링크 단어. 레이아웃이 링크 단어 위치를 계산해 둔다(`Page.links`).
- (선택) 수집한 단어 자리에 회색 단어를 남겨 "긁어 간 흔적" 표시.
