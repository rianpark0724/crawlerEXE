## 1. 개요

웹페이지 속을 기어 다니는 크롤러가 되어, 흩어진 데이터를 **발로 밟아** 수집하고 백신을 피해 다음 페이지로 탈출하는 2D 탑다운 액션 게임.

### 1.1 핵심 재미 (모든 기능은 이 셋 중 하나를 강화해야 한다)
1. **살아 있는 다리** — 스프라이트 애니메이션 없이 IK로 매 프레임 계산하는 다리. 같은 걸음이 없다.
2. **발끝 판정** — 데이터는 발이 착지하는 순간에만 줍는다. 조작은 몸통, 결과는 다리.
3. **몸 = 상태창** — 체력바가 없다. 다리 수가 체력이고, 몸 모양이 조작 방식이다.

### 1.2 목표
- 2주 차 끝: □ 사각형으로 스테이지 1–3을 처음부터 끝까지 플레이할 수 있다 (MVP).
- 4주 차 끝: 크롤러 3종, 스테이지 6개 + 보스, 사운드, 점수·저장까지 완성.

### 1.3 비목표 (하지 않는 것)
- 실제 웹 접속·크롤링, 네트워크 기능 (본편 기준. 실제 페이지를 스테이지로 쓰는 아이디어는 21장 외전)
- 멀티플레이, 키보드 조작, 게임패드
- 스프라이트 시트 애니메이션 (모든 생물은 선·원·사각으로 절차적으로 그린다)
- 가로 스크롤 (페이지는 세로로만 스크롤)

## 2. 용어

| 용어 | 뜻 |

| 크롤러 | 플레이어 캐릭터. 머리 + 마디들 + 다리들 |

| 다리 (leg) | 마디에 붙은 2관절 선. 어깨 → 무릎 → 발 |
| 발 (foot) | 다리 끝점. 바닥에 고정돼 있다가 걸음을 옮긴다 |
| 착지 (landing) | 발이 한 걸음을 끝내고 바닥에 닿는 순간. 수집 판정 시점 |
| 페이지 | 스테이지 하나. 폭 1280px, 세로로 긴 웹페이지 |
| 데이터 조각 | 수집 대상. 문서 속 **파란 링크 단어** (11.3) |
| 다리 파츠 | 밟으면 크롤러가 자라는 아이템 |
| 페이지 출구 | 이 문서에서 링크를 충분히 먹으면 열리는 '다음 문서' 상자. 칸을 밟아 다음 문서를 고른다 (11.3) |
| 사이트 | 스테이지 하나. 링크로 엮인 문서 여러 장 |
| 방문 대기열 | 먹었지만 아직 가 보지 않은 링크의 문서 목록 (실제 크롤러의 크롤 프런티어) |
| 목표 키워드 | 스테이지 시작 때 받는 단어. 사이트 어딘가의 문서에 있고, 먹으면 탈출 |

## 5. 공통 시스템

### 5.1 몸통 따라가기
- 머리(마디 0)만 입력으로 움직인다.
- 마디 i는 마디 i−1과의 거리를 `SEG_SPACING = 19px`로 유지하며 끌려온다 (거리 제약).
- 예외: △ 삼각형은 경로 기록 방식 (6.2), □ 사각형 WAVE 점프 중에는 간격이 늘어남 (6.1.3).

### 5.2 다리 — IK와 걸음
- 각 다리: 어깨 위치(마디 둘레의 고정점), 허벅지 L1, 종아리 L2, 발 위치(월드 좌표).
- 다리마다 무작위 개성: L1 15–24px, L2 17–30px, 임계 거리 11–20px, 걸음 시간 0.07–0.13초.
- **이상적인 발 위치** = 어깨에서 다리 방향으로 `(L1+L2) × 0.62–0.78` 떨어진 점 + 이동 속도 × 0.08초 (앞쪽으로 미리 딛기).
- **걸음 규칙**
  - 발과 이상적인 위치의 거리가 임계 거리를 넘으면 걸음을 시작한다.
  - 같은 마디의 반대쪽 다리가 걷는 중이면 기다린다 (번갈아 걷기).
  - 동시에 걷는 다리는 전체의 절반 이하.
  - 걸음은 걸음 시간 동안 시작점 → 목표점을 ease-in-out 보간.
  - 거리가 임계 거리 × 5를 넘으면 (순간이동 등) 즉시 이상적 위치로 옮긴다.
- **무릎 (2관절 IK)**: 어깨~발 거리 d (clamp: |L1−L2| < d < L1+L2),
  `cos α = (L1² + d² − L2²) / (2·L1·d)`, 무릎 = 어깨 + L1·(cos(θ ± α), sin(θ ± α)). θ = 어깨→발 방향, 부호는 다리 쪽(좌/우)으로 바깥으로 꺾이게.

### 5.3 발끝 수집
- 다리가 **착지하는 순간 한 번** 판정한다. 착지 지점 반경 `COLLECT_R = 18px` 안의 데이터 조각을 모두 수집.
- 몸통·이동 중인 발은 수집하지 않는다.
- 다리 파츠·출구 링크도 같은 방식(착지)으로 밟는다.

### 5.4 피격 · 체력
- **체력 = 다리 수.** 0이 되면 GAME OVER.
- **GAME OVER 연출** (실제로는 거의 머리 하나만 남았을 때): 쿵(0.2초 멈칫·흔들림) → 데이터 유출(머리에서 데이터 조각이 쏟아지며 줌인, 띠의 DATA가 0으로) → 글리치(색 어긋남·눈 ×) → 응답 없음(화면이 하얗게 굳고 주소칸에 `(응답 없음)`) → 오류 대화상자(보고서 작성 막대) → 티어링 → 곧바로 `crawl://lost` 오류 보고서. 약 4.3초.
- 피격 연출: 잘린 다리가 튕겨 날아가 꼼지락, 불꽃, 0.07초 히트스톱, 화면 흔들림, 맞은 마디 번쩍임.
- **다리 피격**: 적의 판정 원과 다리의 두 선분(어깨–무릎, 무릎–발) 중 하나가 겹치면 그 다리가 잘린다 (−1).
- **몸통 피격**: 적과 마디(원 판정)가 겹치면 다리 2개를 잃는다 (꼬리 쪽 마디의 다리부터).
- 잘린 다리는 몸에서 떨어져 바닥에서 1초간 꿈틀거리다 사라진다 (연출).
- **마디 탈락** (□ △): 어떤 마디의 다리가 모두 없어지면 0.8초 바닥에 끌리다가 떨어져 나가고(바닥에서 돌며 1초 동안 흐려짐) 앞뒤 마디가 초당 600px로 당겨져 이어진다. 머리는 탈락하지 않는다.
- 피격 후 `HIT_IFRAME = 1.0초` 무적, 몸이 깜빡인다.
- 다리 수에 따른 이동 속도 배율: 1–2개 ×0.6 / 3–5개 ×0.85 / 6–8개 ×1.0 / 9–12개 ×1.1.
- **다리 불균형** (어느 쪽 다리를 잃었는지에 따라):
  - 끌려감: 움직이는 동안 머리가 다리가 적은 쪽으로 초당 `0.4 × 불균형` rad 돈다 (불균형 = (왼쪽−오른쪽)/전체). 없는 쪽으로 도는 건 쉽고 반대쪽은 어렵다 (회전 ×(1 ± 0.5 × 불균형)).
  - 비틀거림: 짝 없는 다리가 디딜 때 머리가 없는 쪽으로 약 35° × (0.4 + 0.6 × 불균형) 휘청 꺾였다가(순간 느려짐) 다시 커서 쪽으로 돌아온다. 휘청임 사이 최소 0.5초.
  - 기울어짐: 한쪽 다리만 남은 마디는 없는 쪽으로 3px 쏠리고 3px 처진다.
  - 절뚝임: 짝 없는 다리는 걸음 시간 ×1.3, 뗄 때마다 마디가 4px 꺼지고 그동안 속도 ×0.75.
  - 끌림: 다리가 없는 마디는 바닥에 끌리며 먼지, 끌리는 마디마다 속도 ×0.85 (S08-6 탈락 전까지).

### 5.5 우클릭 무적 액션 (공통 규칙)
- 모든 크롤러의 우클릭은 **짧은 무적 + 대가**를 포함한다. 무적은 최대 0.5–0.6초 수준.
- 재사용 대기시간이 있다. 대기 중에는 HUD에 표시.
- 무적 중에는 데이터를 수집하지 않는다.

## 6. 크롤러 3종

### 6.1 □ 사각형 BOX — 기본형 (MVP)
**6.1.1 이동**
- 머리가 커서 방향으로 회전(최대 3.5 rad/s)하며 전진.
- 속도: `120 px/s + 다리 한 쌍당 8 px/s`, 커서와 거리가 가까우면 감속 (거리 × 2.2 상한).
- 시작: 마디 3 · 다리 6 / 최대: 마디 6 · 다리 12.

**6.1.2 성장**
- 다리 파츠 하나 = **마디 +1, 다리 +2** (꼬리에 추가).

**6.1.3 우클릭 — WAVE (점프 돌진 파동)**
- 우클릭하면 커서 쪽으로 **점프하듯 돌진**한다. 머리가 먼저 뛰고, 뒤 마디들이 `0.05초` 간격으로 차례로 뛴다 (몸을 따라 지나가는 파도).
- 마디 i의 점프(체공) 구간 = `[i × 0.05, i × 0.05 + 0.55]` 초 (머리 i = 0). **공중에 뜬 마디가 무적**이다.
  - 공중 마디: 높이가 포물선으로 올라갔다 내려옴(그림자가 멀어짐), **반투명**(유령처럼 통과), 다리는 접어 올리고 걸음을 멈춘다.
  - 공중 마디는 나는 방향으로 길쭉해지고(길이 × 최대 1.35), 착지 순간 0.12초 납작했다(길이 × 0.8) 정사각형으로 돌아온다. 넓이는 유지 (쫀득하게).
  - 착지: 다시 불투명, 다리가 내려와 디딤, 흙먼지와 반동.
- 머리 돌진: 출발할 때 커서 방향으로 고정, 약 `160px`을 체공 시간 동안 이동. **공중에서는 방향을 바꿀 수 없다** (대가).
- 머리가 먼저 멀리 가므로 마디 간격이 잠깐 늘어난다: 아직 땅에 있는 마디는 제자리에 버텨 간격이 최대 `1.6 × 19 = 30px`까지 늘고, 뛰어오른 마디는 앞 마디로 따라붙어 초당 600px로 19px까지 줄어든다 (자벌레처럼 늘었다 줄어드는 파도). 파동이 끝난 뒤 남은 간격도 같은 속도로 복원. 늘어난 마디 사이 선은 가늘고 흐리게.
- **착지 경직**: 머리가 착지하면 `0.1 + 0.7 × (꺾은 각도 / 180°)`초 동안 움직이지도 돌지도 못한다. 바라보던 방향으로 뛰면 0.1초, 뒤돌아 뛰면 0.8초 → 방향 바꾸기용으로 쓰면 손해.
- 재사용 대기: 파동(꼬리 착지)이 끝난 뒤 1.5초. 게이지 HUD는 없다 (F1에만).
- 참고: 몸 전체가 동시에 공중인 시간 = 0.55 − (마디 수 − 1) × 0.05초. 마디 3개면 0.45초, 6개면 0.3초. 지름 32px 위험 지점을 마디 3개는 35–95px, 4개는 35–80px, 6개는 35–65px 앞에서 뛰어야 넘는다 → 긴 몸은 타이밍이 까다롭다 (의도된 대가).

### 6.2 △ 삼각형 TRI — 돌진형 (3주 차)
**6.2.1 이동**
- 마우스 이동만으로는 움직이지 않는다. 커서 위치에 목적지 표시만.
- **좌클릭**: 머리가 즉시 클릭 지점을 향하고 `330 px/s`로 직진. **도착 전에는 방향을 바꿀 수 없다.** 돌진 중 좌클릭 무시.
- 도착 후 0.2초 경직 → 다음 클릭 가능.
- 다리 걸음 시간 ×0.55 (빠르게 종종거림).

**6.2.2 몸통 — 경로 기록**
- 머리가 지나간 점들을 기록하고, 마디 i는 그 경로를 따라 `i × 19px` 뒤의 점에 놓인다. 급선회하면 몸이 꺾인 모양 그대로 뒤따라온다.
- 경로 기록은 몸 길이 + 여유분만 유지.

**6.2.3 성장**: 다리 파츠 하나 = 마디 +1, 다리 +2. 시작 마디 3 · 다리 6.

**6.2.4 우클릭 — FOLD (접기)**
| 단계 | 시간 | 동작 |
|---|---|---|
| 접기 | 0.12초 | 꼬리부터 마디가 머리 쪽으로 당겨져 아코디언처럼 겹침, 다리 오므림 |
| 무적 | 0.5초 | 피격 없음, 수집 없음 |
| 반동 | 0.15초 | 머리 방향으로 40px 밀려나며 펴짐 |
| 경직 | 0.3초 | 클릭 입력 무시 |
- **돌진 중에도 사용 가능.** 사용하면 돌진이 그 자리에서 끝난다.
- 재사용 대기 2.5초.

### 6.3 ○ 원형 ORB — 구르기형 (3주 차)
**6.3.1 이동 (관성)**
- 커서 방향으로 가속, 마찰로 감속, 최고 속도 제한. n = 다리 수:
  - 마찰 `μ = 0.15 + 0.10 n` (/s), 속도에 `max(0, 1 − μ·dt)` 곱함
  - 가속 `a = 520 / (1 + 0.08 n)` (px/s²), 커서가 8px 이상 떨어져 있을 때만
  - 최고 속도 `v_max = 380 / (1 + 0.10 n)` (px/s)
- 다리 4개: 쭉 미끄러짐 · 7개: 보통 · 10개 이상: 잘 멈추지만 느림.

**6.3.2 몸과 다리**
- 마디 없음 (원 하나, 반지름 18px). 몸은 이동 거리만큼 회전한다.
- 다리는 원 둘레에 등간격으로 붙어 몸과 함께 돈다. 발은 5.2 규칙대로 IK로 딛고 걸음을 옮긴다 (구르면서 허둥지둥 걷는 모양).
- 시작 다리 4, 최대 12. 다리 파츠 하나 = **다리 +1만** (마디 없음).

**6.3.3 우클릭 — BALL (말기)**
- 다리를 몸에 붙여 공 모양, 0.5초 무적.
- 그동안 마찰 ≈ 0 (μ × 0.05) → 그대로 미끄러진다 (대가).
- 재사용 대기 2.0초.

## 7. 다리 파츠

| 종류 | 효과 | 대가 | 등장 |
|---|---|---|---|
| 일반 | 성장만 (6장 성장 규칙) | 없음 | MVP |
| 긴 다리 LONG | 붙은 다리 L1·L2 ×1.5 → 수집 범위 증가 | 걸음 시간 ×1.4, 다리 피격 선분도 길어짐 | 3주 차 |
| 가시 SPIKE | 착지 시 반경 40px 안의 백신 봇 1.5초 정지 | 드물게 등장 | 3주 차 |
| 자석 MAG | 착지 시 반경 60px 안의 데이터를 발 쪽으로 끌어당김 | 드물게 등장 | 3주 차 |

- 능력은 그 파츠로 생긴 다리에 붙는다. 그 다리를 잃으면 능력도 사라진다.
- 같은 파츠라도 크롤러별 결과가 다르다: 사각형 = 수집 폭 확장 / 삼각형 = 경로 위 몸 전체가 쓸어 담음 / 원형 = 마찰 증가.

## 9. 적

사이트마다 그 사이트다운 적이 나온다. 위키 사이트(스테이지 1)의 적은 위키백과가 문서를 지키는 방식에서 따왔다.

| 적 | 유형 | 동작 | 판정 | 수치 (초기값) |
|---|---|---|---|---|
| 되돌리기 봇 | 추적 | 평소엔 제자리. 크롤러가 이 문서의 링크를 먹으면 깨어나 크롤러의 **발자국(착지 지점)을 순서대로 되짚어** 따라온다. 발자국을 읽을수록 빨라짐. 먹힌 링크 자리를 지나면 그 링크를 **되돌린다** | 원 r 12 | 속도 70 → 최대 220 px/s |
| 새로 고침 띠 | 패턴 | **화면 기준**으로 위→아래 가로지르는 로딩 띠. 0.5초 전 경고 | 폭 24px 띠 | 주기 4초 · 통과 1.2초 |
| 보호된 문단 | 지형 | 편집 보호 테두리·자물쇠. 닿으면 그 다리 잘림 + 몸 넉백 | 사각형 | 넉백 40px |
| 스팸 봇 (W3) | 무리 | 5–8마리가 한 방향으로 줄지어 페이지를 가로지름 | 원 r 8 | 속도 140 px/s |
| 거대 백신 (W4) | 보스 | 격리 탄 발사, 패치 노드 3곳 생성 | — | 15장 |

- 적은 카메라 화면 + 위아래 200px 안에 있을 때만 움직인다 (활성 범위).
- **되돌리기 봇 상세**
  - 발자국: 착지할 때마다 기록. WAVE로 뛰면 발자국이 끊겨 봇이 마지막 발자국에서 길을 잃고 잠시 헤매다 제자리로 돌아간다.
  - 되돌리기: 먹힌 링크가 다시 파랗게 돌아가고(다시 먹을 수 있음) 데이터 −1, 이 문서 수집 수 −1. 위키 문서 비교(diff)처럼 빨강→초록 줄과 ↺ 표시, `되돌림 −1` 글, 띠의 DATA가 빨갛게 깜빡여 **확실히 보이게**.
  - 그림은 코드로 그리고, 마음에 안 들면 그림 파일로 교체할 수 있게 그리기를 한 함수에 모은다.
- **새로 고침 띠 상세**: 문서에 들어올 때마다 '훑기 직후'부터 시작해 반드시 경고가 먼저 나온다. 띠는 화면 전체를 훑어 WAVE로만 넘을 수 있으므로 한 문서의 띠 간격은 3초 이상 (사이트 검사기가 확인).
- **보호된 문단 상세**: 위치를 숫자로 적지 않고 문서의 실제 문단을 고른다 (`protect`: 개수). 먹을 수 있는 링크·목표 키워드가 놓인 문단, 시작 위치 근처, 출구 바로 위 문단은 제외. 머리는 문단 안으로 들어갈 수 없다(무적 중에도).
- 되돌리기 봇은 다리를 자른 뒤 1.2초 멈춘다 (가만히 있다 연달아 잘리지 않게), 최대 속도 180 px/s.

## 10. 페이지 · 스크롤 · 카메라

웹페이지를 위에서 아래로 읽어 내려가는 느낌이 핵심이다.

### 10.1 페이지
- 폭 1280px 고정, 높이는 스테이지마다 다름 (720–2880px, 화면 1–4장).
- 시작 지점은 페이지 위쪽, 출구 링크는 대개 아래쪽.
- 배경: 그 페이지 종류(백과사전, 뉴스 등)를 닮은 **읽을 수 있는 흐린 글**과 화면 구성. 실제 사이트를 레퍼런스로 삼는다.
  - 스테이지 1 `/wiki/crawler`: **위키백과(Vector 2022) 어두운 테마**를 레퍼런스로 머리글·목차·탭·제목·안내문·본문·그림 틀·각주·분류·바닥글까지 재현. 내용은 **웹 크롤러 "생물"에 대한 짧은 토막글**(아직 밝혀진 게 거의 없는 느낌, 튜토리얼 힌트를 담음). 로고·그림은 직접 제작한다 — `tools/make_wiki_images.py`가 표준 라이브러리로 그려 `assets/images/`에 저장(파일이 없으면 X 자리 표시). 글꼴은 맑은 고딕(없으면 pico2d 기본 글꼴).
  - 페이지 글 전체 밝기는 `WIKI_ALPHA`로 낮춰 크롤러가 잘 보이게 한다.
- 데이터 조각은 이 글 위에 놓인 단어다. 외전(21장)에서는 실제 웹페이지 글과 링크 단어가 그대로 들어간다.

### 10.2 카메라
- **세로로만 스크롤.** `camera.y` = 화면 아래쪽 가장자리의 월드 y. 범위 `[0, page_height − 720]`.
- 머리가 화면 가운데 40% 구간(데드존)을 벗어나면 그쪽으로 따라간다. 부드럽게: `camera.y += (target − camera.y) × min(1, 6·dt)`.
- `/video/stream`: 카메라가 30 px/s로 자동으로 내려간다. 화면 **위쪽** 밖으로 밀려난 다리는 잘린다.

### 10.3 좌표 변환
- 화면 y = 월드 y − camera.y
- 마우스: `screen_y = 719 − event.y`, `world_y = screen_y + camera.y`. 카메라가 움직이면 커서 월드 좌표도 매 프레임 다시 계산 (마우스를 가만히 둬도 목표가 같이 움직인다).

### 10.4 HUD 스크롤바
- 화면 오른쪽 끝에 웹 브라우저 같은 세로 스크롤바. 현재 보이는 구간 + 출구 링크(주황 점) + 남은 데이터(하늘색 점)의 위치를 표시.

- 해금: 스테이지 3 클리어 → △ 삼각형, 스테이지 5 클리어 → ○ 원형.

### 11.2 스테이지(사이트) JSON 스키마 (`data/stages/<id>.json`)
```json
{
  "id": "wiki",
  "url": "/wiki/",
  "pages_dir": "wiki",
  "start": "웹 크롤러",
  "targets": [{"page": "백신", "keyword": "격리"}, {"page": "방화벽", "keyword": "차단"}],
  "min_pages": 3,
  "min_hops": 2,
  "page_quota": 3,
  "par_time": 150,
  "dark": false,
  "pages": {
    "웹 크롤러": {"parts": {"plain": 1}, "enemies": {"bot": 1}},
    "백신": {"enemies": {"bot": 2}, "beams": [{"axis": "h", "period": 4.0, "offset": 0.0}]}
  }
}
```
- 문서는 `data/pages/<pages_dir>/*.json` (제목·본문 블록, 배치 정보 없음). 문서끼리는 **제목**으로 가리킨다.
- `targets`: 목표 후보 `(문서, 키워드)`. 시작할 때 하나를 무작위로 뽑는다 (11.3-7).
- `pages.<제목>`: 그 문서의 파츠·적은 **종류별 개수**만 적고 위치는 무작위(11.3-7). 빔·방화벽은 위치를 직접 적는다 — 문서 높이가 글 길이로 정해지므로 **y는 0(맨 아래)~1(맨 위) 비율**, x는 px.
- 문서 높이 = 레이아웃 결과(최소 720). 시작 위치 = 문서 맨 위 가운데.
- 문서 표기: `[[제목]]` 파란 링크(그 제목의 문서가 사이트에 있을 때) · `[[!단어]]` 빨간 링크(문서 없음, 먹을 수 없음) · `**굵게**` · `[1]` 각주 · `{{키워드|대체어}}` 목표 키워드가 들어갈 수 있는 자리 (뽑힌 자리 하나만 금색 키워드, 나머지는 대체어로 평범하게 보임).
- `parts` 종류: `plain | long | spike | mag`. `enemies.type`: `bot | spam | boss`. `walls`는 `[x, y비율, w, h]`.

### 11.3 사이트와 링크 이동 (방문 대기열)
1. 스테이지 시작 화면에서 **목표 키워드**를 받는다 (예: "격리"). 시작 문서(`start`)의 맨 위에서 출발.
2. **파란 링크 = 데이터 조각.** 발로 착지하면 먹는다: 데이터 +1, 단어가 방문한 링크 색(보라)으로, 그 링크의 문서가 **방문 대기열**에 들어간다. 빨간 링크는 먹을 수 없다.
3. 이 문서에서 링크를 `page_quota`개 먹으면 **먹은 링크 껍데기(보라)**가 주황 점선으로 반짝이며 '갉을 수 있는 곳'이 된다. 껍데기 위에 **몸을 1.2초 올려 두면**(내려오면 게이지가 빠짐) 페이지가 갉아먹혀 구멍이 뚫리고, 크롤러는 구멍으로 빨려 들어가 **그 링크의 문서 맨 위로 떨어진다.** 갉을 때 글자 부스러기가 머리로 빨려 들어가고, 구멍이 부러진 판자처럼 벌어지며 0과 1이 새어 나온다. 링크를 다 먹은 직후 1.2초는 갉을 수 없다. 지나온 문서가 있으면 왼쪽 위 여백의 `← 뒤로` 껍데기로 돌아갈 수 있다. 출구 상자·클릭 선택은 없다 (모든 상호작용은 크롤러로).
   - 링크 이름을 보고 목표 키워드가 어느 문서에 있을지 **추리**하는 것이 이 구조의 재미.
4. **목표 키워드**는 목표 문서 본문에 금색 단어로 있다. 발로 먹으면 탈출(CLEAR) — 단 **방문한 문서가 `min_pages`장 이상**이어야 한다. 모자라면 "크롤링이 부족하다" 표시만 나고 다시 먹을 수 있다.
5. 문서를 넘어가도 다리 수·체력·데이터 수는 유지된다. 이미 먹은 링크는 다시 먹을 수 없다(다시 방문해도 보라).
6. 사이트 설계 규칙: 문서마다 파란 링크 4–8개, 목표 문서는 시작에서 링크 2단계 이상 떨어지게, 링크 이름이 목표 쪽 힌트가 되게.
7. **무작위 (매 판 다르게)**
   - **목표**: `targets` 후보 중 하나를 뽑는다. 단 시작 문서에서 링크로 **도달할 수 있고 `min_hops`단계 이상** 떨어진 후보만 (불러올 때 링크 그래프를 너비 우선 탐색으로 검사).
   - **키워드 위치**: 목표 문서의 `{{키워드|대체어}}` 자리 중 하나를 뽑아 금색 키워드로, 나머지는 대체어로.
   - **파츠·적 배치**: 문서마다 정한 개수를 무작위 위치에. 링크 단어·출구·시작 위치 근처는 피한다.
   - 시작 문서는 고정 (스테이지 1 튜토리얼). 스테이지 2부터는 후보 중 뽑기를 검토.
   - `config.RANDOM_SEED`에 숫자를 넣으면 매번 같은 판 (시연·버그 재현용), `None`이면 매번 다르게.

## 12. 화면 흐름 · HUD

```
crawl://home ──▶ 사이트 (문서들) ──▶ crawl://transfer (이동 중) ──▶ 다음 사이트 … 마지막 ──▶ crawl://final (깔때기 · 최종 점수) ──▶ 처음부터 / home
     ▲                     └──▶ crawl://lost ──▶ 다시 / home
     └──────────────────────────────────────────┘
```
- **원칙: 크롤러는 화면에서 사라지지 않는다.** 메뉴·결과·사이트 이동도 전부 크롤러가 걸어 다니는 **페이지**이고, 선택은 칸을 밟아서 한다 (클릭 선택·멈춘 메뉴판 없음). 페이지 사이는 '새 창 열기' 연출(11.3-3).
- `crawl://…` 페이지는 사이트가 아니라 **크롤러 브라우저 자체 페이지** — 어느 사이트와도 다른, 위쪽 띠와 같은 톤.
- MVP(2주 차)에서는 사이트 선택 없이 home → 스테이지 1 → 2 → 3 순서로 진행 (`config.STAGE_ORDER`). 몸·데이터·시간은 판 전체로 이어진다.
- ESC 일시정지: 세상(적·시간·카메라)은 멈추고 화면이 어두워지며 가운데에 `계속`·`다시 크롤링`·`홈` 칸. 크롤러만 움직여 칸 위에 서서 고른다(ESC 다시 누르면 계속). 일시정지 중 움직임은 메뉴 고르기일 뿐 — 계속하면 멈췄던 자리로 돌아가고 링크도 먹지 않는다. 게임 종료는 홈의 `종료` 칸 또는 창 닫기.
- **HUD** (화면 좌표, 스크롤과 무관하게 고정)
  - 화면 맨 위 **브라우저 띠** (높이 36px, 사이트가 바뀌어도 모양 고정 — 페이지는 띠 아래 창으로 보임): `CRAWL.EXE` · 주소칸 `crawl://wiki/백신` · 목표칸 `🔍 목표 격리` · 오른쪽 `방문 2/3  문서 1/3  DATA 07` (채운 조건은 초록) (다리 수는 HUD 없이 몸으로 보임)
  - 오른쪽 아래 붙은 능력 파츠 `[LONG] [MAG]` (우클릭 대기시간 게이지는 두지 않음)
  - 오른쪽 끝 스크롤바 (10.4)
- 체력바 없음. 크롤러 몸이 상태 표시.

## 13. 점수 · 해금 · 저장

- 점수 = 데이터 × 10 + 남은 다리 × 50 + max(0, par_time − 클리어 시간) × 5 — 한 판 전체로 계산 (par_time은 세 사이트 합, 시간은 크롤러가 깔때기에서 다 갈린 순간까지). crawl://final에서 깔때기 입구 테두리에 다리가 뜯길 때·주둥이에서 흘러나온 데이터가 통에 떨어질 때마다 점수가 올라감
- 등급: S ≥ 기준 × 1.2 / A ≥ × 1.0 / B ≥ × 0.8 / C 나머지 (기준 점수는 테스트 후 스테이지별 결정)
- 저장 `data/save.json`: 스테이지별 최고 점수·등급·사용 크롤러, 해금 상태. (git 제외)
- 개발자 옵션: 타이틀에서 F12 → 전부 임시 해금, `[DEV] ALL UNLOCKED` 표시, 저장하지 않음.

## 15. 보스 — 거대 백신 (4주 차)

- 한 화면 아레나(높이 720). 중앙의 보스가 3초마다 격리 탄 4–6발을 퍼뜨린다 (탄 속도 160 px/s, 다리 피격 판정).
- 바닥에 패치 노드 3개(반경 30px)가 생긴다. **발 3개 이상이 동시에 노드 하나 위에 착지 상태**로 0.5초 유지되면 과부하 1회.
- 과부하 3회 = CLEAR. 과부하마다 탄 패턴이 빨라진다.

## 21. 외전 — 실제 웹페이지 크롤링 (MVP 이후 아이디어)

> 본편 범위가 아니다. 본편이 끝난 뒤 시간이 남으면 하는 확장. 일정에 넣지 않는다.

### 21.1 아이디어
- 실제 주소(URL)를 받아 **그 웹페이지의 글을 그대로 페이지로** 깔고, 그중 몇몇 단어가 **밟을 수 있는 데이터 조각으로 변한다.**
- 크롤러는 진짜 문서 위를 기어 다니며 진짜 링크 단어를 발로 긁어모은다 — "크롤러"라는 설정을 문자 그대로 구현.

### 21.2 방식 (검토 결과)
| 방식 | 판단 |
|---|---|
| 헤드리스 브라우저로 화면 스크린샷 | ✗ 큰 의존성, 이미지라 단어 위치를 알 수 없음 |
| 게임 실행 중 실시간 접속 | △ 시연 중 네트워크 실패 위험, 매번 결과가 달라 밸런스 불가 |
| **변환 도구 `tools/url_to_stage.py`** | ○ 표준 라이브러리(`urllib`, `html.parser`)로 HTML → 스테이지 JSON 저장. 게임은 JSON만 읽음 |

- 변환 규칙(초안): 제목·문단 → 페이지 글줄, `<a>` 링크 텍스트 → 데이터 조각 후보, 높이 = 글 길이, 목표 = 링크 수의 일부, 적·파츠는 규칙으로 자동 배치.
- 한계: 레이아웃은 문서 구조를 흉내 낼 뿐 실제 CSS 모양이 아님. 자바스크립트로 그리는 사이트(SNS·쇼핑몰 대부분)는 본문이 거의 없다 → 위키·뉴스 기사 위주.
- 추가 옵션: SELECT에 "주소 입력" — 실패하면 기본 스테이지로.

### 21.3 본편에서 미리 맞춰 둔 것
- 페이지 = 문서 JSON(`data/pages/`) + 위키 레이아웃 코드. 변환 도구는 실제 페이지의 제목·문단·링크를 **같은 문서 형식**(`[[링크]]` 표기)으로 내보내기만 하면 된다 — S03-2a에서 적용.
- 데이터 조각 = 문서 속 파란 링크 단어. 레이아웃이 링크 단어 위치를 계산해 둔다(`Page.links`).
- (선택) 수집한 단어 자리에 회색 단어를 남겨 "긁어 간 흔적" 표시.
